動作環境

  • Hardware
    • Macbook Pro M2Pro(Unified Memory: 32G)
  • Software
    • LM Studio
    • ollama

今回のテーマ

せっかくRAGという概念を知ったので、自分でRAGを作ってみたくなったのがきっかけ。
某草の根ネット(net-cock)の通信ログがなぜか手元にあるので、それを使ってみたいと思いました。

理想的なゴールは以下の問いに対して、適切に答えてもらうこと。
「双◯溶断がスポスタ不買運動を言い出したのは、いつのどのボードの発言ですか？」

そのためにLangChainやDifyを使ってみました。
あと、できれば全部無料でやりたい、というのがあります。
将来的にDGX Sparkを買いたいなと考えていますが、今のところもっと使い込む要素がないとただの無駄遣いになってしまいますね…。

通信ログの正規化

チャッピーに相談して、通信ログは正規化しておいたほうが良いですよ、ということで正規化のロジックを作ってもらいました。
結論から言うと結局これを使わない方が効率が良かったです。

LangChainでやってみた

このpythonでは

  • text embeddingにollama + nomic-embed-text:latest
  • 推論用に ollma + gemma:latest と gpt-oss:20b を使いました。　

「軍歌」についての話題が出ていたので、バスの中で軍歌を歌うのは誰ですか？と質問してみました。

Difyでやってみた

ナレッジに、ログファイルをいくつかsjis→utf-8、および拡張子変更をし、追加しました。 また、ログファイルにシリアルヘッダが入っていたため（不正なエスケープシーケンス付き）それも除去しました。

登録の際にGemini3を使用。
どうやら間髪入れずリクエストを発行しているようでレートリミットにすぐに到達。

LM Studioでやった時

ワークフロー作成

  • 知識検索がうまくできなかった

    • 理由は、システムモデルの設定がOpenAI/GPT-3.5になっていたため。
      アカウント→設定→モデルプロバイダーで設定をするも反映をしない模様。
      ワークフロー一覧画面でDSL exportして、テキストを見たらGPT-3.5のままになってました。
      手動で書き換えて、インポート。

  • 知識検索の結果を結果ノードで直接出せない
    • いくら見ても知識検索のresultがないので、調べたら一度LLMを通す必要があり。 ここでモデルはlm studio + GPT-OSS-20bを指定しましたが… lm studioのプラグインがmodeをサポートしていないため、lm studio側でpydantic errorが出ました。 →ollamaのGPT-OSS-20bを設定。

最終的にembeddingもollamaにまかせてgot kotonaki。
